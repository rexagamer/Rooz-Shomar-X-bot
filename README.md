# روزشمار (RoozShomarX) 📅

بات تلگرامی برای ثبت تاریخ‌های مهم به **تقویم شمسی**، دیدن اینکه از هر تاریخ چند روز گذشته (یا چند روز مونده) و **اشتراک‌گذاری تاریخ‌ها با دوستان** از طریق کد. روی Telegram Serverless اجرا می‌شه؛ نه سرور می‌خوای، نه دیتابیس بیرونی.

## ۱. معرفی

- ثبت تاریخ با عنوان (مرحله‌به‌مرحله: سال ← ماه ← روز ← عنوان ← تأیید)
- نمایش تاریخ‌ها با ارقام فارسی و اختلاف روز (روزِ تقویمی، نه ساعت)
- ویرایش و حذف (با تأیید)
- ساخت کد اشتراک برای همه یا بعضی تاریخ‌ها؛ دوستت با `/import` اون‌ها رو به لیست خودش اضافه می‌کنه
- ابطال کد (کپی‌هایی که قبلاً وارد شدن حذف نمی‌شن)
- فقط چت خصوصی؛ منطقه زمانی پیش‌فرض `Asia/Tehran`
- بازه‌ی سال‌های پشتیبانی‌شده: ۱۳۰۰ تا ۱۵۰۰ (قاعده‌ی حسابی ۳۳ ساله)

## ۲. پیش‌نیازها

- Node.js نسخه ۱۸ یا بالاتر (`node -v`) و npm
- حساب تلگرام و دسترسی به `@BotFather`
- ترمینال (PowerShell در ویندوز)

## ۳. ساخت بات در BotFather

۱. در تلگرام `@BotFather` رو باز کن.
۲. `/newbot` رو بفرست.
۳. یه نام نمایشی بده (مثلاً «روزشمار»).
۴. یه نام کاربری یکتا بده که به `bot` ختم بشه.
۵. **Bot API Token** رو جایی امن نگه دار.
۶. تنظیمات بات رو باز کن (`/mybots` ← انتخاب بات).
۷. بخش **Serverless** رو پیدا کن و فعالش کن.
۸. داخلش دنبال **CLI Access** (دسترسی CLI) بگرد و **Access Token** رو بساز/کپی کن.

> ⚠️ برچسب منوها ممکنه با نسخه‌ی فعلی BotFather کمی فرق داشته باشه؛ دنبال «Serverless» و «CLI Access» بگرد.

> ⚠️ **دو توکن متفاوت داریم:**
> - **Bot API Token**: برای صدا زدن Bot API. توی `tgcloud login` استفاده نمی‌شه.
> - **Serverless CLI Access Token**: همونیه که `npx tgcloud login` می‌خواد.
>
> هیچ‌کدوم رو توی کد نذار و توی Git کامیت نکن.

## ۴. شروع با پروژه

```powershell
cd RoozShomarXbot
npm install
```

`npm install` فقط ابزار `@tgcloud/cli` رو نصب می‌کنه (وابستگی توسعه). خودِ بات هیچ پکیج npm ای نیاز نداره.

## ۵. اتصال به بات

```powershell
npx tgcloud login
```

CLI توکن رو می‌پرسه؛ **Serverless CLI Access Token** رو بده. اطلاعات اتصال در پوشه‌ی `.tgcloud/` (مثلاً `.tgcloud/state.json`) ذخیره می‌شه. این پوشه باید در `.gitignore` بمونه و هرگز کامیت نشه.

## ۷. اجرای تست‌ها

```powershell
npm test
```

اگر تستی خراب شد، پیام `assert` نشون می‌ده مقدار واقعی (`actual`) با مقدار مورد انتظار (`expected`) چقدر فرق دارن. تست `static.test.js` خطاهای import (پسوند `.js` نداشتن، import غیرمجاز) رو می‌گیره.

## ۸. تست Handler بدون Deploy

```powershell
npx tgcloud run handlers/message "{ chat: { id: 123, type: 'private' }, from: { id: 123 }, text: '/start' }"
```

این یه پیام ساختگیه، نه پیام واقعی تلگرام. چون `chat.id` واقعی نیست، ارسال پاسخ ممکنه با خطای **`chat not found`** تموم بشه؛ این لزوماً باگ منطق نیست. برای دیدن پاسخ واقعی، `id` رو شناسه‌ی عددی خودت بذار. این دستور به **دیتابیس واقعی** هم وصل می‌شه، پس جدول‌ها باید قبلاً migrate شده باشن.

## ۹. Deploy و Migration

```powershell
npx tgcloud status     # تفاوت پروژه‌ی محلی با ابر
npx tgcloud push       # ارسال ماژول‌ها (و schema) به ابر
npx tgcloud migrate    # اعمال تغییرات schema روی دیتابیس (تعاملی)
npx tgcloud webhook    # بررسی تطابق webhook با handlerها
```

- `push` کد را منتشر می‌کند و فقط گزارش می‌دهد دیتابیس چه تغییری **خواهد کرد**؛ **چیزی روی دیتابیس اعمال نمی‌کند**.
- `migrate` تغییرات schema را واقعاً اعمال می‌کند. قبل از تأیید، لیست تغییرات را بخوان.
- از گزینه‌های مخرب استفاده نکن.
- اگر `npx tgcloud webhook` ناهماهنگی نشان داد: `npx tgcloud webhook sync`.

ترتیب اولین بار: `status` ← `push` ← `migrate` ← `webhook`.

## ۱۰. منوی دستورات (`/setcommands`)

در BotFather: `/setcommands` ← انتخاب بات ← این متن را بفرست:

```
start - شروع و نمایش تاریخ‌های من
add - ثبت تاریخ جدید
list - نمایش تاریخ‌ها
today - تاریخ امروز و تاریخ‌های من
edit - ویرایش یک تاریخ
delete - حذف یک تاریخ
share - ساخت کد اشتراک‌گذاری
import - دریافت تاریخ‌ها با کد
myshares - مدیریت کدهای اشتراک
cancel - لغو عملیات فعلی
help - راهنما
```

## ۱۱. استفاده از بات

۱. `/start` ← خوش‌آمد و لیست تاریخ‌ها.
۲. `/add` ← سال (`۱۴۰۴`)، ماه (`۳` یا `خرداد`)، روز (`۱۵`)، عنوان (`شروع رابطه`) ← **✅ ثبت تاریخ**. ارقام فارسی، عربی و انگلیسی قبول است.
۳. `/list` ← لیست با «N روز گذشته / باقی‌مونده».
۴. `/edit` ← انتخاب تاریخ ← ویرایش عنوان یا تاریخ ← تأیید.
۵. `/delete` ← انتخاب تاریخ ← تأیید حذف.
۶. `/share` ← «اشتراک همه» یا «انتخاب تاریخ‌ها» ← کد نمایش داده می‌شود؛ برای دوستت بفرست.
۷. دوستت: `/import ABCD-EFGH-JKLM-NPQR` ← پیش‌نمایش ← **✅ اضافه کن**. ایمپورت دوباره، تکراری نمی‌سازد (عنوان و تاریخ یکسان).
۸. `/myshares` ← لیست کدهای فعال ← **🚫 ابطال**. کد بعد از ابطال دیگر کار نمی‌کند، اما تاریخ‌هایی که قبلاً وارد شده‌اند می‌مانند. متن کد ذخیره نمی‌شود؛ پس فقط موقع ساخت قابل مشاهده است.
۹. `/cancel` ← لغو هر مرحله‌ی نیمه‌کاره (مراحل نیمه‌کاره بعد از ۲۴ ساعت منقضی می‌شوند).

## ۱۲. عیب‌یابی

- **فقط «You said: …» می‌گیرم:** هنوز handler قدیمی روی ابر است. `npx tgcloud status` و بعد `push`.
- **بات اصلاً جواب نمی‌دهد:** `npx tgcloud webhook` را بزن؛ در صورت ناهماهنگی `webhook sync`. مطمئن شو `handlers/message.js` و `callback_query.js` خالی نیستند و push شده‌اند.
- **«مشکلی پیش اومد» برای همه‌ی دستورها:** احتمالاً `migrate` اجرا نشده (جدول‌ها وجود ندارند) یا کوئری‌های `db-store.js` با SDK نمی‌خوانند. لاگ را بررسی کن.
- **`tgcloud login` خطا می‌دهد:** احتمالاً Bot API Token داده‌ای؛ باید CLI Access Token باشد.
- **Serverless غیرفعال:** در BotFather فعالش کن.
- **تاریخ نامعتبر:** اسفند در سال کبیسه ۳۰ روز دارد؛ ماه‌های ۱–۶ سی‌ویک روز و ۷–۱۱ سی روز.
- **کد پیدا نشد:** کد را درست کپی کن؛ کد ممکن است باطل شده باشد. بعد از ۵ تلاش ناموفق، ۱۵ دقیقه باید صبر کنی.
- **توی گروه کار نمی‌کند:** عمدی است؛ فقط چت خصوصی.
- **تغییرات اعمال نمی‌شوند:** `push` کن؛ برای تغییر schema بعدش `migrate`.

## ۱۳. امنیت و حریم خصوصی

- بات فقط پیام‌هایی را می‌بیند که خودت برایش می‌فرستی.
- لیست تاریخ‌ها خصوصی است؛ هر کوئری با شناسه‌ی صاحب انجام می‌شود.
- کد اشتراک فقط به همان snapshot دسترسی می‌دهد، نه بقیه‌ی تاریخ‌های تو.
- فقط هش کد ذخیره می‌شود.
- ابطال کد جلوی ایمپورت‌های بعدی را می‌گیرد ولی کپی‌های قبلی را پاک نمی‌کند.
- توکن‌ها را هرگز در کد یا Git نگذار.
